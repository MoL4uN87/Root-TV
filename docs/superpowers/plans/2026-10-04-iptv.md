# IPTV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace NTV-PLUS pages with a direct HLS IPTV screen that supports verified built-in channels and safe user M3U playlists.

**Architecture:** A focused IPTV module validates and parses playlist data. The loopback helper fetches external playlist and HLS manifests, while the webOS app keeps playlist URLs in localStorage, renders cards, and sends only validated HLS URLs to its existing native video player.

**Tech Stack:** JavaScript compatible with Node 8 and webOS browser APIs, existing loopback Node helper, HTML/CSS, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-04-iptv-design.md`

## Global Constraints

- Accept only HTTPS URLs with no credentials, port, private address, or local host.
- Limit downloaded playlists to 2 MB and 500 channel records.
- Send only validated HTTPS `.m3u8` URLs to the native player.
- Preserve Kinozal, Sport, history, cache, and TorrServer behavior.
- Use Russian messages for user-visible errors.

## Review Focus

- An M3U URL with embedded credentials must be rejected before any request.
- A playlist above 2 MB must produce a size error without retaining partial channels.
- A playlist with malformed `#EXTINF` records must retain valid later records only.
- A selected HLS URL returning HTML or a non-M3U body must not open the player.
- An expired child HLS manifest must preserve the saved playlist and show an actionable error.
